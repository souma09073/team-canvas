# コード解説 — マンジャロ日本縦断

このゲームの中身を、**自分の言葉で説明できるようにする**ための資料。
「どこに何が書いてあるか」と「なぜそうしたか」をまとめている。

対象:`processing/manjaro/`(Processing で `manjaro.pde` を開くと全ファイルがタブで開く)

---

## 1. まず知っておくこと

このゲームは **3D** で動いている。ただし 3Dモデルは1つも使っていない。
主人公も食べ物も、Processing に最初から入っている **球(`sphere`)と箱(`box`)** を
3次元の座標に置いているだけ。

**遠近感の計算は一切していない。** カメラを主人公の後ろに置けば、
遠くのものが小さく見えるのは Processing が勝手にやってくれる。

```
カメラ:主人公の後ろ11・高さ5     ─→  camera() で指定
物の位置:(横, 高さ, 前後)         ─→  translate() で移動して sphere() を描くだけ
```

## 3. 毎フレーム何が起きているか

`manjaro.pde` の `draw()` が1秒間に60回呼ばれる。

```
① 経過時間(dt)を測る          ← millis() の差。フレームレートに左右されないため
② game.update(dt)             ← ルールの処理。血糖が減り、進み、当たり判定をする
③ view.apply() / drawWorld()  ← 3Dを描く
④ hud.draw()                  ← 2Dを上に重ねる
```

**なぜ dt を掛けるのか:** PCによって1秒間の描画回数が違う。
「1フレームで血糖を0.2減らす」と書くと、速いPCでは速く減ってしまう。
「1秒で10減らす」と書き、経過時間を掛けることで、どのPCでも同じ速さになる。

## 4. ゲームのルール(`Game.pde`)

### 血糖値がこのゲームの中心

- 初期値 50。**何もしないと毎秒10ずつ減る**
- 食べ物を取ると **+20**
- **0 になると低血糖で死ぬ**
- **65 を超えると高血糖のカウントダウンが始まり、3秒以内に65以下へ戻さないと死ぬ**

つまり「食べ続けないと死ぬが、食べすぎても死ぬ」。
必要なペースは **20 ÷ 10 = 2秒に1個**。

### マンジャロ(スペースキー)

前方の食べ物をまとめて消す。**7秒に1回しか使えない。**

この7秒は、**現実のマンジャロが週1回しか投与できないことの再現**。
ゲーム内の7秒 = 現実の7日として圧縮している。
だから画面表示も「補充中」ではなく「次回投与まであと○日」にしてある。

使うと2秒間、**食べても血糖が上がらなくなる**(薬が吸収を抑える作用)。
ただし**血糖の低下は止まらない**(通常の80%で下がり続ける)。
これは意図的で、**低血糖のリスクを消さないため**。
完全に止めてしまうと「打てば安全」になり、薬の危険性が表現できなくなる。

### ゾーン(Zキー)

血糖を緑(35〜65)に保つと溜まる。満タンで発動すると1.5秒だけ1.8倍速になり、
**女性をすり抜けられる**。ただし**食べ物はすり抜けない**。

ゾーンから無敵をあえて外している。安全地帯にしてしまうと、
マンジャロを使う理由が無くなってしまうため。

### 女性キャラ

ぶつかると7秒間マンジャロが使えなくなる。地面の下に隠れていて、
**1.2秒手前で急にせり上がる**。

出現を「距離」ではなく「時間」で決めているのが要点。
序盤(速度70)と終盤(速度196)で速度が3倍違うので、距離を固定にすると
終盤は反応する暇が無く運任せになってしまう。

## 5. コースの作り方(`Course.pde`)

### 毎回まったく同じコースになる

`mulberry32` という乱数を使い、**種(seed)を固定**している。
乱数といっても、同じ種からは必ず同じ数列が出る。だからタイムを競える。

### 配置の原則:1列に置くのは最大2個

**必ず1レーンは空けている。** 3個並べて絶対に避けられない場所を作ると、
プレイヤーは理不尽に感じて面白くなくなる。

**例外は終盤の「壁」だけ。** ここは3レーン全部を塞ぐ。
ただし**マンジャロで消せる**ので、回避手段がないわけではない。
「レーン移動では抜けられないが、道具を使えば抜けられる」という判断を作っている。

壁の手前には**看板が立っている**。壁が見えてから撃つのでは
クールタイム(7秒)が間に合わないので、8秒手前で予告している。

## 6. 数値を変えたいとき(`Config.pde` だけ触る)

| やりたいこと | 変える値 |
|---|---|
| コースを長く / 短くする | `COURSE_LENGTH_SEC`(今55秒) |
| 速くする / 遅くする | `BASE_SPEED`(序盤70)、`RAMP_END_MULT`(ゴール時2.8倍) |
| 血糖メーターの動きを穏やかにする | `FOOD_GAIN` と `DRAIN_PER_SEC` を**同じ倍率で**下げる |
| 低血糖で死にやすくする | `DRAIN_PER_SEC` を上げる |
| 高血糖で死にやすくする | `DRAIN_PER_SEC_HIGH` を**下げる**(下がるのが遅くなる) |
| 高血糖の難しさを一気に緩める | `HYPER_GRACE_SEC` を上げる(安全弁) |
| 食べ物を増やす / 減らす | `SPARSE_GAP_MIN` `SPARSE_GAP_MAX`(間隔。大きいほどまばら) |
| 密集地帯の位置を変える | `Course.pde` の `zones`(コース長に対する割合) |
| マンジャロの間隔 | `SHOT_COOLDOWN`(今7秒 = 現実の1週間) |
| ゾーンの溜まりやすさ | `ZONE_CHARGE_PER_SEC`(今8 = 満タンまで12.5秒) |

### 変えるときの注意

- **`FOOD_GAIN` と `DRAIN_PER_SEC` はセットで考える。**
  必要ペース = `FOOD_GAIN ÷ DRAIN_PER_SEC` 秒に1個。
  両方を同じ倍率で変えれば、忙しさは変えずにメーターの跳ね方だけ調整できる
- **`STABLE_MAX` を変えるときは `HYPER_THRESHOLD` と `HYPER_RESET_BELOW` も同じ数字にする**(3ヶ所セット)
- **高血糖で死ぬ条件:** `(100 - 65) ÷ DRAIN_PER_SEC_HIGH` が `HYPER_GRACE_SEC` を超えると
  「振り切ったら確定死」になる。今は 35÷15 = 2.33秒 対 3秒 で、余裕は0.67秒しかない

## 7. つまずきやすい所

**日本語が □ になる**
Processing の標準フォントは日本語を出せない。`Fonts.pde` が候補を上から試して、
そのPCに入っているものを選んでいる。全部無ければコンソールに警告が出る。

**別のPCで画面からはみ出す**
`size(1280, 720)` を決め打ちにすると、画面の小さいPCで収まらない。
そこで**描画は常に1280×720の座標で書き、表示するときだけ拡大縮小**している。
`Hud.pde` の `computeDesignTransform()` と `begin()` がその処理。

**HUD が3Dモデルに埋まる / 3Dが壊れる**
2Dを3Dの上に重ねるには `hint(DISABLE_DEPTH_TEST)` で奥行き判定を切る必要がある。
描き終わったら `ENABLE_DEPTH_TEST` で**必ず戻す**。戻し忘れると次のフレームの3Dが壊れる。

**主人公の横のバーが変な所に出る**
3Dの座標を画面座標に変換する `screenX()` は、**3Dのカメラが有効な間しか正しい値を返さない。**
そのため HUD がカメラをリセットする前に計算している(`manjaro.pde` の `computeMiniGaugePos`)。

## 8. HTML版との関係

`prototype/prototype.html` はブラウザで動く検証用。ゲーム設計はここで詰めた。
Processing版はその**完全な移植**で、乱数まで同じにしてあるため、
**同じ種から1個の狂いもなく同じコースが生成される**。

起動時にコンソールへ照合結果が出る:

```
コース長  7315 units   (期待 7315)
食べ物    153 個   (期待 153)
女性      7 体   (期待 7)
壁        z=5917-6112   (期待 5917-6112)
```

数値を変えたときは、HTML版と Processing版のどちらを「正」とするか決めること。
現在は **Processing版が提出物**なので、そちらを正とする。
